# NodeMCU ESP8266 + MicroPython quickstart

Всё что надо чтобы прошить NodeMCU ESP8266, загрузить примеры или заюзать REPL.

Нужен just, curl и uv. Все рецепты:

```bash
just
```

Поставить инструменты через `uv`, скачать прошивку, прошить плату, запихнуть туда blink и открыть repl:

```bash
just setup
```

Если не заработает сразу, можно посмотреть, может порт у платы другой:

```bash
just ports
```

Загрузить код на плату (сразу как основной `main.py`):

```bash
SCRIPT=scripts/10-blink.py just put-script
```

Открыть REPL:

```bash
PORT=/dev/ttyUSB0 just repl
```

Выйти из `mpremote repl`: `Ctrl-]`. Остановить запущенный скрипт: `Ctrl-C`. Перезагрузить пллату: `Ctrl-D`.

## Скрипты-примеры

- `scripts/10-blink.py` - мигает встроенным LED на GPIO2 / D4.
- `scripts/20-science-art-morse.py` - мигает фразу `SCIENCE ART` азбукой Морзе.
- `scripts/30-wifi-hotspot-led.py` - поднимает Wi-Fi точку доступа и простую HTML-страницу с кнопками для ВКЛ/ВЫКЛ светодиода.
- `scripts/40-button-led.py` - хардварная кнопка на D0 / GPIO16 включает светодиод.
- `scripts/50-button-serial.py` - хардварная кнопка шлет `button:pressed` / `button:released` в serial.

## Карта пинов NodeMCU

В коде MicroPython нужен GPIO-номер, а не надпись `D0`, `D1` и т.д. на плате:

| На плате | В коде |
| --- | --- |
| D0 | `Pin(16)` |
| D1 | `Pin(5)` |
| D2 | `Pin(4)` |
| D3 | `Pin(0)` |
| D4 | `Pin(2)` |
| D5 | `Pin(14)` |
| D6 | `Pin(12)` |
| D7 | `Pin(13)` |
| D8 | `Pin(15)` |
| RX | `Pin(3)` |
| TX | `Pin(1)` |
| A0 | `ADC(0)` |

Если кнопка подключена к `D0`, значит в коде это `Pin(16)`.
На `D4 / GPIO2` есть встроенный светодиод. Он обычно active-low: `0` включает, `1` выключает.

Осторожно с пинами: `D3 / GPIO0`, `D4 / GPIO2`, `D8 / GPIO15`. Они могут мешать старту платы, если во время старта на них неправильный уровень. Лучше не трогать их до полной загрузки и не выставлять им режим `PULL_UP` например.
`D0 / GPIO16` тоже особенный: его часто используют для работы с питанием, но в целом его можно использовать для детектирования ввода от кнопки например. Просто запомните что он особенный и у него не такие же interrupt-возможности как у остальных GPIO.

На практике это означает простое правило: что-то не работает -- поменяй пин.

Для Wi-Fi примера по дефолту сеть `science-art-esp8266` с паролем `scienceart`
После подключения адрес обычно `http://192.168.4.1/`, но если что в REPL можно подсмотреть что там.

## Идеи заданий для закрепления

**Базовое**
- Поменять скорость моргания в блинкере
- Поменять фразу в морзянке
- Поменять сеть и пароль в wifi-примере
- Поменять HTML страничку (приветствие, цвета) 

**Посложнее**
- Хардварная кнопка для управления светодоиодом (ну то есть не полениться всё подключить и загрузить [соответствующий пример](./scripts/40-button-led.py))
- Подключить внешний светодиод к тому же пину что и внутренний, убедиться что они мигают в разные фазы
- Добавить пищалку в морзе. Подумать. Учесть выводы из предыдущего пункта

**Хардкорненько**
- Разобраться с примером с serial и кнопкой/воркером на ноутбуке.

Тут сложность в том как это запускается, потому что у нас один шнурок до ноутбука и по нему же мы прошиваем и туда цепляется по умолчанрию REPL, а мы его же пытаемся читать. Поэтому надо немного хитро запускать сам скрипт и слушать что приходит.
Аналогично с OSC


- Добавить ADC-потенциометр и выводить значения на ноут (read A0)

```python
from machine import ADC

adc = ADC(0)
value = adc.read()
print(value)
```

Не посылайте на A0 слишком большой ток. На большинстве плат есть делитель, поэтому можно посылать от 0 до 3.3В, но лучше перепроверить это или перестраховаться и считывать не больше вольта.

Кнопка на плате тоже может менять что-то на экране ноутбука через serial.
Это несложно: на ESP8266 скрипт делает `print("button:on")`, а на ноутбуке Python-скрипт читает `/dev/ttyUSB0` через `pyserial` и обновляет окно, терминал или веб-страницу. Самая простая версия занимает примерно два маленьких файла.

### Serial

:warning: примеры с Serial имеют больше сложностей в настройке чем в самом программировании. Постарайтесь не упустить суть

Для serial примера с кнопкой воркер-скрипт на ноутбуке сам запускает скрипт на плате через `mpremote run` и читает события:

```bash
just button-worker
```

Это запускает `scripts/50-button-serial.py` на плате. Кнопка по умолчанию на D1. Пример с OSC (для подключения к Max / TouchDesigner):

```bash
just button-osc-worker 
```

Шлет `1` или `0` на OSC-адрес `/esp/button`, по дефолту на `127.0.0.1:8000`.

Если после прошлых экспериментов всё ведёт себя странно, надо закрыть все окна где REPL или serial, на плате найти и нажать reset, а если совсем не помогло -- `just flash`.
